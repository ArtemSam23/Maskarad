**Живой стенд:** [maskarad.tech](https://maskarad.tech) — демо-интерфейс и `POST https://maskarad.tech/process` для прогона организаторов · [maskarad.tech/docs](https://maskarad.tech/docs) — документация API · метрики и логи — в Monium (доступ по запросу).

Прокси между системой-потребителем и LLM: находит персональные данные (ПДн) в запросе, маскирует их до отправки в модель и восстанавливает в ответе. Правила, набор типов ПДн, вид маски и право на демаскирование настраиваются **на каждую систему-потребителя** в одном YAML-файле, без правки кода. Реализует контракт автопроверки `POST /process`.

```
 Система-потребитель ──► Maskarad ──► идентификация ──► маскирование ──► LLM
                           ▲                                              │
                           └────────────── демаскирование ◄───────────────┘
```

Ядро — Rust (`axum`, `regex`, `aho-corasick`), без ML в горячем пути: 10 000 запросов/с на 4 ядрах при p99 ≈ 1.6 мс, текст на 100 000 токенов — за 0.5 с. Один бинарник ≈ 10 МБ со встроенными словарями.

## Быстрый старт

Бинарник (нужен Rust ≥ 1.80):

```bash
cargo build --release
./target/release/maskarad serve --config config/maskarad.yaml
# http://localhost:8080 — демо-интерфейс, /metrics, /readyz
```

Стенд целиком (сервис + Redis + Prometheus + Grafana с готовым дашбордом):

```bash
docker compose -f deploy/docker-compose.yml up --build
# UI http://localhost:8080 · Grafana http://localhost:3000 (admin/admin) · Prometheus http://localhost:9090
```

Kubernetes: локально — `kubectl apply -k deploy/k8s/overlays/local`; продуктив в Яндекс Облаке (`maskarad.tech`) создаётся и обновляется полностью из GitHub Actions — см. [infra/README.md](infra/README.md).

Переменные окружения, которые читает `config/maskarad.yaml`: `MASKARAD_LISTEN`, `MASKARAD_STORE` (`memory`|`redis`), `REDIS_URL`, `MASKARAD_STORE_KEY` (ключ шифрования хранилища), `MASKARAD_SECRET` (секрет для стратегий `token`/`synthetic`), `MASKARAD_ADMIN_KEY`, `LLM_BASE_URL`, `LLM_API_KEY`, `MASKARAD_DEMO_MODE`, `MASKARAD_LOG_FORMAT`, `MASKARAD_LOG_LEVEL`.

## Проверка для жюри за 5 минут

**1. Контракт `/process`** — первый запрос с новым `payload_id` маскирует, второй с тем же `payload_id` демаскирует:

```bash
curl -s -X POST localhost:8080/process -H 'Content-Type: application/json' \
  -d '{"payload":"Клиент Иванов Иван Иванович, паспорт 4509 123456","payload_id":"demo-1"}'
# {"result":"Клиент И. И. И., паспорт 45** ****56"}

curl -s -X POST localhost:8080/process -H 'Content-Type: application/json' \
  -d '{"payload":"Клиент И. И. И., паспорт 45** ****56","payload_id":"demo-1"}'
# {"result":"Клиент Иванов Иван Иванович, паспорт 4509 123456"}
```

**2. Демо-интерфейс** `http://localhost:8080`: вставьте любой текст, нажмите «Замаскировать» — подсветка найденных типов с основанием («почему»), текст, который уйдёт в модель, кнопка обратного восстановления и, при настроенном `LLM_BASE_URL`, живой вызов модели через прокси с демаскированным ответом. В выпадающем списке — примеры: все 17 типов, регистр и форматы дат, разделяющие слова, ловушки (Пушкин, адрес отделения банка, даты и города без контекста), документы кроме паспорта РФ.

**3. Ловушки** — ничего не маскируется:

```bash
./target/release/maskarad mask "Поэт Александр Пушкин родился 6 июня 1799 года в Москве"
./target/release/maskarad mask "Отделение банка по адресу г. Москва, ул. Каланчёвская, д. 27 работает до 20:00"
```

**4. Логи** — stdout, JSON, ровно одна строка на каждый запрос к API (`/process`, `/v1/mask`, `/v1/demask`, `/v1/detect`, `/v1/chat/completions`), включая отказы, и на запрос по неизвестному пути: `request_id` (он же в заголовке ответа `X-Request-Id`), маршрут (`route`: шаблон маршрута, у неизвестного пути — `unmatched`), код ответа (`status`), время обработки (`duration_ms`), система, направление, хэш `payload_id`, размер текста, число токенов, **найденные типы ПДн с количеством** (`"types":"FIO:1,PASSPORT:1"`), состояние хранилища. У отказов обработчика есть код ошибки (`code`), у отказа допуска при перегрузке — ещё `reason`: `adaptive_limit` (адаптивный лимит коротких запросов при нехватке CPU), `large_lane_full` (большой текст не дождался своей полосы) или `inflight_limit` (потолок `server.max_inflight`), см. [docs/design.md, §12.1](docs/design.md#121-защита-от-перегрузки). Ответы, которые дал не обработчик, — `413` (тело больше `server.max_body_bytes`), `503` по `server.request_timeout_ms`, `404`, `405` — пишутся строкой `request rejected` с `route`, `status` и `duration_ms`, без `code`. Запрос, который клиент оборвал до ответа, пишется строкой `request aborted` со `"status":499`; запрос, на котором обработчик запаниковал, — строкой ERROR `request panicked` без `status`: ответа клиент не получает, соединение закрывается. Служебные маршруты (`/healthz`, `/readyz`, `/metrics`, `/v1/systems`, `/v1/types`, `/v1/profiles`, `/admin/reload`, `/docs`, `/docs/openapi.json`, `/docs/openapi.yaml`, `/`) строк не пишут. Значений ПДн и текста запросов в логах нет по построению (см. [Безопасность](#безопасность-логи-метрики)), поля всех строк перечислены в [docs/design.md, §11](docs/design.md#11-безопасность-логи-метрики). Читаемый формат: `MASKARAD_LOG_FORMAT=pretty`. В облаке строки уходят в Monium Logs, см. [infra/README.md](infra/README.md#логи-и-диагностика).

```json
{"timestamp":"2026-09-23T07:55:45.151289Z","level":"INFO","message":"masked","request_id":"bb5640ac7296ee88","route":"/process","direction":"mask","system":"alfasonar","payload_id_hash":"c4b887415867","text_bytes":108,"tokens":23,"entities":3,"types":"FIO:1,PHONE:1,SNILS:1","store":"memory","degraded":false,"status":200,"duration_ms":0.68,"target":"maskarad::handlers::process"}
{"timestamp":"2026-09-23T07:55:49.598606Z","level":"WARN","message":"request rejected","request_id":"ec2a415e8c67491c","route":"/process","code":"RATE_LIMITED","status":429,"reason":"adaptive_limit","target":"maskarad::limits"}
{"timestamp":"2026-09-23T08:28:56.681014Z","level":"WARN","message":"request rejected","request_id":"1b58f5372d083b7c","route":"/process","status":503,"duration_ms":102.64,"target":"maskarad::logging"}
```

**5. Метрики** — `GET /metrics` (Prometheus): latency (`maskarad_request_duration_seconds`), RPS (`maskarad_requests_total`), TPS (`maskarad_tokens_total`), найденные типы (`maskarad_pii_detected_total`), 429, состояние хранилища и LLM. Готовый дашборд — в `deploy/grafana/`: Grafana в локальном docker-compose, в облаке тот же дашборд импортируется в Monium.

**6. Настройка систем** — `GET /v1/systems` показывает, что включено для каждой системы; таблица есть и в UI. Отредактируйте `config/maskarad.yaml` (например, `enabled: false` у системы или другой `profile`) — файл перечитывается на лету, перезапуск не нужен.

**7. Качество и нагрузка** — `make eval` (отчёт в `docs/quality.md`), `./target/release/maskarad bench --url http://localhost:8080 --rps 500 --duration 30` (500 пар/с = 1000 запросов/с по протоколу проверки), результаты замеров — в [docs/performance.md](docs/performance.md).

## Как это работает

Конвейер на каждый запрос: **normalize → detect → resolve → mask**, демаскирование — отдельная операция по сохранённому соответствию.

| Стадия | Что делает |
|---|---|
| Normalize | Копия текста в нижнем регистре (`ё`→`е`, типографские тире и NBSP унифицированы) с картой смещений в оригинал: регистронезависимость получается конструктивно, а маска ставится в исходный текст. |
| Detect | Три семейства детекторов. *Pattern* — регулярные выражения из справочника [`crates/maskarad-core/builtin/types.yaml`](crates/maskarad-core/builtin/types.yaml) с валидаторами (Luhn, контрольные суммы ИНН и СНИЛС, валидность дат, правдоподобность телефона) и контекстными окнами; для карт, ИНН и СНИЛС валидатор «мягкий» (`soft_validator: true`): значение с неверной контрольной суммой всё равно маскируется, если рядом есть слово «карта»/«ИНН»/«СНИЛС» — пропуск дороже ложного срабатывания. *Gazetteer* — один автомат Aho-Corasick по ~8 000 форм городов, регионов и стран. *Composite* — ФИО (любой порядок, инициалы, падежи, 84 тыс. фамилий, правила отчеств), адрес из компонентов (индекс, регион, город, улица, дом, квартира), место рождения, гражданство, орган выдачи паспорта, имя держателя карты, даты в 7 написаниях (`дд.мм.гггг`, `гггг.дд.мм`, `12 мая 1987`, `мая 12, 1987`, словами). |
| Resolve | Решает, ПДн ли это: контекстные слова усиливают (`паспорт`, `выдан`) или подавляют (`поэт`, `отделение банка`); справочники исключений (публичные персоны, адреса отделений, горячие линии, корпоративные домены); «слабые» сущности (CVV без карты, голая дата, город без адреса) — только с контекстом или сущностью-компаньоном; правила комбинаций системы; пересечения решаются по силе доказательств, затем по приоритету типа. |
| Mask | Стратегия на тип из профиля системы. Одинаковое значение в тексте получает один и тот же плейсхолдер — включая падежные формы (`Иванова Ивана Ивановича` = `Иванов Иван Иванович`) и разные написания номера. |
| Demask | По позициям, если пришла ровно наша маска (контракт), иначе подстановкой масок в переписанный моделью текст — сначала длинные, повторы по порядку, плейсхолдеры без учёта регистра. |

Подробности и обоснования — в [docs/design.md](docs/design.md).

## Настройка

Все настройки — в `config/maskarad.yaml`. Чтобы подключить систему-потребителя, добавьте запись в `systems` с её `id`, ключом (`auth.api_keys`), перечнем типов ПДн (`pii_types`), флагом `demask` и профилем маскирования (`profile`); `enabled: false` отключает доступ. Новый тип ПДн добавляется записью в `pii_types` (регулярное выражение, контекст, валидатор, стратегия) без правки кода. Ловушки — публичные персоны, адреса отделений, корпоративные телефоны и домены — перечисляются в `allowlists`. Файл перечитывается на лету; ошибочная версия не применяется, действует предыдущая.

Пример системы:

```yaml
systems:
  - id: support-chatbot
    description: "Чат-бот поддержки"
    auth: { api_keys: ["sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"] }  # или открытый ключ
    pii_types: [FIO, PHONE, EMAIL, CARD_NUMBER, CVV, PIN, PASSPORT, ADDRESS]   # или all
    exclude_types: [DATE]
    demask: true                      # false — система не может демаскировать
    profile: placeholder              # reference | placeholder | synthetic | token | full | свой
    overrides:                        # стратегия на отдельный тип поверх профиля
      CARD_NUMBER: { kind: partial, keep_start: 4, keep_end: 4, mask_chars: digits }
    weak_entities: context_only       # context_only | always | never
    address_mode: whole               # whole | components
    combination_rules:                # контекстное маскирование
      - { mask: PIN, only_if_present: [CARD_NUMBER] }
```

Новый тип ПДн (пример из `config/maskarad.yaml`):

```yaml
pii_types:
  - id: EMPLOYEE_ID
    description: "Табельный номер сотрудника"
    patterns: ['(?:^|[^а-яa-z0-9])(?P<v>тн-?\d{6})(?-u:\b)']   # группа v — значение
    context: { before: ['табельн', 'сотрудник'], required: false }
    validator: none                   # none | luhn | inn | snils | date | phone | { digits_len: { min: 6, max: 6 } }
    confidence: 0.9
    priority: 60
```

Шаблоны работают по тексту в нижнем регистре; чтобы движок регулярных выражений оставался на быстром DFA, ставьте `(?-u:\b)` только рядом с цифрами и латиницей, а перед кириллическим словом используйте поглощающий префикс `(?:^|[^а-яa-z0-9])` и группу `v` для значения. Запись с `id` встроенного типа переопределяет его целиком (так можно поменять контекстные слова или выключить тип: `enabled: false`). Свой профиль:

```yaml
profiles:
  compliance:
    description: "Инициалы для имён, остальное — звёздочки"
    default: full
    types: { FIO: initials, CARD_HOLDER: initials }
```

Секции `server` (лимиты, таймауты), `store` (Redis, TTL, ключ шифрования, `timeout_ms`, `memory_capacity_bytes`, `memory_fallback`), `llm` (upstream), `admin`, `logging`, `ui`, `masking.secret` описаны в комментариях `config/maskarad.yaml`. Проверить файл без запуска: `maskarad check-config --config config/maskarad.yaml`; применить на работающем сервисе: сохранить файл или `POST /admin/reload` с админ-ключом.

## Профили маскирования: какой выбрать

| Профиль | Пример | Для чего |
|---|---|---|
| `reference` | `Иванов Иван Иванович` → `И. И. И.`, `4509 123456` → `45** ****56`, `12 мая 1987` → `** *** ****` | Контракт автопроверки и системы, которым нужен «человекочитаемый» замаскированный текст. Демаскирование — только по позициям (текст не должен меняться). |
| `placeholder` | `<FIO_1>`, `<PHONE_1>`, `<ADDRESS_2>` | **Всё, что ходит в LLM.** Плейсхолдер уникален и стабилен внутри запроса, модель переносит его в ответ, ответ демаскируется в любом порядке и регистре. |
| `synthetic` | `Иванов Иван Иванович` → `Бабинков Леопольд Леопольдович`, карта → валидная по Луну фейковая | Модель или аналитика видят правдоподобные данные; один и тот же человек всегда получает одну и ту же синтетику (детерминированно от `masking.secret`). |
| `token` | `tok_9f2a1c4b7e…` | Необратимые стабильные токены (HMAC) для склейки контекста между запросами без раскрытия значения. |
| `full` | `ivanov@mail.ru` → `******@****.**` | Позиционная маска звёздочками. |

Почему для LLM нужен именно `placeholder`: позиционная маска вроде `** *** ****` теряет информацию, и после того как модель переформулирует текст, однозначно восстановить её нельзя ни в одной реализации. Плейсхолдер же — непрозрачный идентификатор, который модель копирует, а сервис подставляет обратно.

## API

Интерактивная документация: [/docs](http://localhost:8080/docs) (ReDoc), спека — [/docs/openapi.yaml](http://localhost:8080/docs/openapi.yaml) и `/docs/openapi.json`. Спека собирается из кода (`utoipa`) при каждом запросе, отдельно генерировать и коммитить её не нужно.

| Метод | Назначение | Авторизация |
|---|---|---|
| `POST /process` | Контракт: `{payload, payload_id}` → `{result}`. Первый запрос с `payload_id` маскирует, повтор того же текста возвращает ту же маску (ретраи безопасны), запрос с нашей маской демаскирует, изменённый текст демаскируется подстановкой. | анонимная система (`auth.anonymous: true`) или `X-API-Key` |
| `POST /v1/mask` | `{text, payload_id?}` → `{payload_id, masked, entities[{type,start,end,confidence,evidence,mask}], degraded}` | `X-API-Key` / `Authorization: Bearer` |
| `POST /v1/demask` | `{text, payload_id}` → `{text, entries}` | ключ; система с `demask: true` |
| `POST /v1/detect` | `{text}` → сущности без маскирования | ключ |
| `POST /v1/chat/completions` | OpenAI-совместимый прокси: `messages[].content` маскируются (общие плейсхолдеры на весь диалог), запрос уходит в `llm.base_url`, `choices[]` демаскируются. Потребитель меняет только `base_url`. | ключ |
| `GET /v1/systems`, `/v1/types`, `/v1/profiles` | Настройки только для чтения | админ-ключ (или демо-режим) |
| `POST /admin/reload` | Перечитать конфигурацию | админ-ключ |
| `GET /healthz`, `/readyz`, `/metrics` | Проверки и метрики | — |
| `GET /docs`, `/docs/openapi.yaml`, `/docs/openapi.json` | Документация API: ReDoc и спека OpenAPI | — |

Ошибки — единый формат `{"error":{"code":"DEMASK_FORBIDDEN","message":"…","request_id":"…"}}`: `INVALID_REQUEST` 400, `UNAUTHORIZED` 401, `SYSTEM_DISABLED`/`DEMASK_FORBIDDEN` 403, `MAPPING_NOT_FOUND` 404, `RATE_LIMITED` 429 с `Retry-After`, `STORE_BUSY` 429 с `Retry-After: 1` (только `/process`: хранилище не ответило, запрос надо повторить), `STORE_UNAVAILABLE` 503 (`/v1/*`), `LLM_UNAVAILABLE` 502 / `LLM_TIMEOUT` 504. Не в едином формате: `413` при превышении `server.max_body_bytes` (текст от axum), `503` по `server.request_timeout_ms`, `404` и `405` (пустое тело). Каждый ответ API-маршрутов, включая эти отказы, и ответ `404` на неизвестный путь несёт `X-Request-Id` — id его строки в логе; ответы служебных маршрутов (`/healthz`, `/readyz`, `/metrics`, `/v1/systems`, `/v1/types`, `/v1/profiles`, `/admin/reload`, `/docs`, `/docs/openapi.json`, `/docs/openapi.yaml`, `/`) его не несут. Ответы `/process` — ещё `X-Maskarad-Direction` и, при деградации хранилища, `X-Maskarad-Degraded`.

В демо-режиме (`ui.allow_system_override: true`) запросы `/v1/*` могут указывать поле `system` без ключа — для показа разных профилей в UI; в промышленной конфигурации режим выключен.

## Качество

Golden-датасет — синтетический: генератор с фиксированным seed (`maskarad gen`) покрывает все 17 категорий ТЗ, сложные предложения со всеми типами сразу, вариации написания (регистр, порядок ФИО, инициалы, 8 форматов дат, «серия … номер …») и 29 ловушек без ПДн; плюс 40 рукописных случаев из ТЗ (`tests/golden/curated.jsonl`). `maskarad eval` считает precision/recall/F1 по типам, **утечку** (символы ПДн, оставшиеся открытыми), сходство маски с эталоном (1 − нормированный Левенштейн — метрика проверяющей системы) и точность обратного восстановления.

Текущий отчёт — [docs/quality.md](docs/quality.md): 1 140 записей, micro-F1 1.000, утечка 0 %, ловушки 29/29 чистые, demask(mask(x)) = x для 100 %. Честная оговорка: генератор и детекторы написаны одной командой, так что это проверка самосогласованности и регрессий, а не независимая оценка; независимой служит эталонный датасет организаторов. Слабые места известны и перечислены в [ограничениях](#ограничения-и-план-развития).

```bash
make eval                               # отчёт в docs/quality.md
cargo test --workspace                  # 66 unit-тестов ядра и сервиса (тест против живого Redis — при MASKARAD_TEST_REDIS_URL)
./target/release/maskarad mask "текст"  # быстрый разбор одной строки с основаниями
```

## Производительность

Замеры встроенным генератором (`maskarad bench`), воспроизводящим протокол проверки: пары «маскирование → демаскирование» с одним `payload_id`, до 3 попыток, ожидание по `Retry-After`, сравнение восстановленного текста с исходным. Один узел, **4 ядра, генератор и сервис на одной машине**, корпус — golden-датасет (100–500 символов на запрос), 30 с на точку.

| Хранилище | Нагрузка | Ошибок / 429 | Маскирование p50 / p95 / p99, мс | Демаскирование p50 / p95 / p99, мс |
|---|---|---|---|---|
| memory | 1 000 запросов/с | 0 / 0 | 0.37 / 0.86 / 1.18 | 0.17 / 0.24 / 0.29 |
| memory | 2 000 запросов/с | 0 / 0 | 0.34 / 0.76 / 1.02 | 0.16 / 0.24 / 0.29 |
| memory | **10 000 запросов/с** | 0 / 0 | 0.53 / 1.08 / 1.55 | 0.23 / 0.66 / 1.03 |
| redis | 1 000 запросов/с | 0 / 0 | 0.53 / 0.97 / 1.25 | 0.15 / 0.22 / 0.27 |
| redis | 2 000 запросов/с | 0 / 0 | 0.55 / 0.95 / 1.20 | 0.15 / 0.23 / 0.28 |

Текст на ~110 000 токенов (847 КБ, 17 577 сущностей) маскируется за 0.55 с и демаскируется за 0.016 с одним запросом `/process`; методика и профиль стадий — в [docs/performance.md](docs/performance.md). При нехватке CPU сервис сразу отвечает `429` с `Retry-After: 1`, а не растит очередь: адаптивный лимит держит задержку коротких запросов, большие тексты ждут своей полосы, `server.max_inflight` — общий потолок ([docs/design.md, §12.1](docs/design.md#121-защита-от-перегрузки), замер — [docs/performance.md](docs/performance.md#перегрузка-адаптивный-допуск)).

Что даёт такую скорость: детекция за один-два прохода по тексту (`RegexSet`-префильтр, DFA-совместимые шаблоны, один автомат Aho-Corasick для справочников, hash-lookup лемм для имён), ноль аллокаций в горячих циклах, `mimalloc`, мультиплексированное соединение с Redis и L1-кэш в памяти (демаскирование на той же реплике не ходит в Redis; кэш ограничен по байтам — `store.memory_capacity_bytes`, по умолчанию 256 MiB), большие тексты — на отдельном пуле потоков, чтобы не блокировать сетевой реактор. Горизонтально — реплики за балансировщиком с общим Redis (`deploy/k8s`, HPA).

## Безопасность, логи, метрики

- **ПДн не попадают в логи и метрики по построению**: все значения сущностей живут в типе `Sensitive<T>`, у которого нет `Display`, а `Debug` печатает `[REDACTED]`; логи содержат только идентификаторы, типы, количества, длины и тайминги; тела запросов не логируются; сообщения об ошибках не содержат текста запроса. Паника пишется одной строкой `panic` с местом в коде (`panic_location`), без сообщения: сообщение паники может цитировать текст запроса, а стандартный обработчик печатает его в stderr, который уходит в хранилище логов вместе с stdout.
- **Ограниченный круг систем**: allowlist в конфигурации, ключи `X-API-Key`/`Bearer`, в конфиге можно хранить только SHA-256 ключей; `enabled: false` — мгновенное отключение; анонимный доступ — только для одной явно помеченной системы (контракт `/process`).
- **Хранилище соответствий**: значения в Redis зашифрованы AES-256-GCM (ключ — из секрета), ключи записей — хэши `payload_id`, TTL на каждой записи, запись только создаётся (`SET NX`) и никогда не перезаписывается; исходный текст целиком не хранится — только найденные сущности; при `store.backend: memory` данные не покидают процесс.
- **Минимизация**: наружу (в LLM) уходит только замаскированный текст; в ответах API нет оригиналов, кроме результата демаскирования, разрешённого системе.
- **Метрики Prometheus**: `maskarad_request_duration_seconds{route,system,direction}` (latency), `maskarad_requests_total{route,status}` (RPS), `maskarad_tokens_total{direction}` (TPS), `maskarad_pii_detected_total{type,system}`, `maskarad_stage_duration_seconds{stage}`, `maskarad_inflight`, `maskarad_rejected_total{reason}`, `maskarad_admission_limit`, `maskarad_admission_rtt_seconds`, `maskarad_admission_rtt_noload_seconds`, `maskarad_admission_lag_seconds`, `maskarad_store_ops_total{op,result}` (`result=exists` — запись уже была), `maskarad_store_retries_total{op}`, `maskarad_store_degraded`, `maskarad_llm_requests_total`.
- В репозитории нет ключей и реальных ПДн: датасеты синтетические, секреты — через переменные окружения.

## Надёжность и деградация

| Отказ | Поведение |
|---|---|
| Redis не отвечает | команда повторяется один раз после таймаута (`store.timeout_ms`, по умолчанию 1 с); если не помогло — `/process` отвечает `429 STORE_BUSY` + `Retry-After: 1`, `/v1/*` — `503 STORE_UNAVAILABLE`; `readyz` → `degraded`, метрика `maskarad_store_degraded=1`, заголовок `X-Maskarad-Degraded`; демаскирование, пришедшее на реплику с записью в L1-кэше, продолжает работать; после восстановления Redis — обычный режим без вмешательства |
| Ошибка чтения или записи хранилища на `/process` | `429 STORE_BUSY` с `Retry-After: 1` — состояние `payload_id` неизвестно, поэтому направление не угадывается и маска вместо оригинала не выдаётся; проверяющая система повторяет запрос (до 3 попыток), и повтор даёт тот же результат. Соответствие попадает в память реплики только после подтверждения Redis, так что записи, видимой одной реплике и невидимой соседним, не бывает |
| Redis недоступен при старте | при `store.memory_fallback: true` реплика поднимается на памяти процесса и сразу помечается `degraded` (её соответствия невидимы другим репликам); при `false` — сервис не стартует |
| LLM недоступен / таймаут | `502`/`504` с сообщением, circuit breaker (после N ошибок — быстрый отказ на время cooldown) |
| Перегрузка | `429 RATE_LIMITED` + `Retry-After: 1` сразу, без очереди: при нехватке CPU — адаптивный лимит коротких запросов; большие тексты ждут своей полосы до половины `server.request_timeout_ms`; потолок `server.max_inflight`; таймаут обработки → `503` |
| Невалидный запрос | `400` с описанием поля; неизвестная / выключенная система — `401`/`403` |
| Ошибка в конфигурации при reload | остаётся предыдущая версия, ошибка в логе |
| Останов | graceful shutdown: новые соединения не принимаются, текущие запросы завершаются |

## Дополнительные возможности

Реализовано из п. 6 ТЗ / п. 3.7 критериев:

1. **Токенизация и синтетика** — стратегии `token` (HMAC) и `synthetic` (детерминированные правдоподобные значения: имена с согласованием пола, Luhn-валидные карты, валидные ИНН, даты в том же формате).
2. **Вид маскирования под систему** — профили, `overrides` на тип, свои профили в конфиге.
3. **Повышенная нагрузка** — 10 000 запросов/с на 4 ядрах при p99 ≈ 1.6 мс (в 10 раз выше требования).
4. **Документы кроме паспорта РФ** — СНИЛС (с контрольной суммой), загранпаспорт, водительское удостоверение, военный билет, свидетельство о рождении, ВНЖ, полис ОМС, банковский счёт, срок действия карты.
5. **Контекстное маскирование по комбинации** — `combination_rules` (например, PIN только вместе с номером карты) и политика «слабых» сущностей (`context_only` / `always` / `never`).

Сверх списка: консистентные плейсхолдеры с учётом падежей и разных написаний, кореференция («Иванов Иван Иванович … Иванову»), OpenAI-совместимый прокси с общими плейсхолдерами на весь диалог, hot-reload конфигурации, встроенный нагрузочный генератор по протоколу проверки, демо-интерфейс.

## Ограничения и план развития

- ФИО ищутся по словарям (84 тыс. фамилий, 900 имён с падежными формами и уменьшительными) и морфологическим эвристикам; редкие иностранные имена без контекста могут быть пропущены, а капитализированное слово перед именем и отчеством — принято за фамилию. План: NER-модель (ONNX) как ещё один детектор с бюджетом времени, включаемый на систему.
- Границы «органа, выдавшего паспорт» и свободных адресов — эвристические (ограничители, грамматика адреса); адреса без маркеров («Тверская 7») распознаются хуже. План: справочник улиц (ФИАС) в газеттире.
- Даты, полностью написанные словами, поддерживаются в основных формах; экзотические написания могут не распознаться.
- Публичные персоны — справочник (~300 имён) плюс слова-подсказки; нужный банку список дополняется в `allowlists`.
- Стриминг ответа LLM (`stream: true`) в прокси пока выдаётся целиком; демаскирование потока с буферизацией на границах плейсхолдеров — следующий шаг.
- Изменение `store` и `llm` секций требует перезапуска (остальное перечитывается на лету).
- Оценка качества — на синтетическом датасете; для банка следующий шаг — разметка реальных обезличенных обращений и калибровка порогов на них.
